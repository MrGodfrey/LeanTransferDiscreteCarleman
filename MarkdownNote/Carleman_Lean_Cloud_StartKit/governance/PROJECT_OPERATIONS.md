# 可持续运行的最小工作约定

**核心原则：任务有边界，项目无固定截止日期。** 一次 Codex 云端任务只接受一个可验证目标，例如“形式化周期分部求和”或“完成 Section 5 的重构残差消去”，不是“直到整篇论文全部证明完才停止”。

监督者每次醒来先查看：是否已有 RUNNING 任务 → 是否已有待审 PR → 用量是否可得与是否触发暂停 → 最近稳定提交/当前数学阻塞 → 才决定是否发新任务。执行者不自行更改本项目的付费额度策略。

所有严肃进展保存在版本化仓库，不依赖 Dot 的记忆：
- `state/progress.json` 机器读取；
- `governance/PROOF_LOG.md` 人类可读；
- pull requests 记录可审核 diff；
- Lean build / CI 记录可复现检查；
- `paper/` 论文源保持只读，修改论文应另起明确 PR。

一个验收通过的单位应当具有**可指认的 Lean 声明与 commit**。无法继续时仍然应提供有数学内容的失败记录，尽可能包含报错、最小反例或精确未能证明的引理，而不是泛泛说“困难”。

任务失败后的重试必须先改变策略或缩小范围，禁止因超时/额度不足对同一不可行任务进行无限次重试。
