# Codex Web 任务接续模板

由 Dot 按实际台账填入以下信息，不从旧对话猜测：

- 仓库与已发布环境：<URL / 环境 ID>
- 台账 ID / 平台 task ID 或链接：<可定位身份>
- 本次模式：<继续原任务 / 合并后新任务 / 独立任务>
- 当前分支 / base_commit：<分支 / 完整 SHA>
- 目标与论文定位：<claim 或 coverage ID、TeX label、PDF 页码>
- 验收条件与依赖：<应证明的声明、范围、目标构建>
- 未合并 PR / 检查点：<URL、SHA；没有则明确写无>
- 阻塞、已试路线、下一步：<精确内容>

读取 `AGENTS.md` 与台账并核实分支/HEAD。未合并代码、CI 错误或审核反馈继续原任务和分支；不要用新任务覆盖原进展。新任务必须从明确已合并基线开始。

完成一个有价值的可核验单元；证明未完成也推送有用检查点。交付 PR：证明了什么、声明位置、论文标签、实际检查 SHA/CI、额外前提、未解依赖和下一步。不要伪造通过检查；不要直接覆盖整个总状态。检查目标须包含成果模块。

将成果交回 Dot 验收/合并；如需修正，继续同一任务。任务交付不表示整个项目暂停：监督者在合并并核实新基线后接续下一项。数学阻塞只阻塞相关目标，独立工作继续。
