# 长期运行约定

## 职责和唯一台账

用户于 2026-10-18 将开发移至本机，并明确授权直接在 `main` 工作，验证后 commit、push，常规阶段不再要求 PR 或云端派单。2026-10-20 用户要求以尽快且正确完成形式化为目标简化流程：本地验证与独立数学验收是日常推进依据；远端 CI 是后台环境复现检查，不再作为每批验收门槛。网页展示筛选过的快照。`state/progress.json.tasks` 是唯一任务台账，不另建重复数据库或第二监督入口。

每条任务记录 ID、可定位的平台 task、目标/验收/依赖、分支与 `base_commit`、状态、提交/检查点、声明和构建证据、阻塞、已试路线、下一步。当前执行任务统一整合总状态，避免并行覆盖。源代码推送仓库，环境缓存和对话不能替代版本化成果。

## 接续与合并

1. 核实真实本地任务、main/远端 HEAD 和台账，先处理不一致。已有运行任务不重复启动。
2. 同目标继续原 task，在 main 保存有意义的检查点；证明构建失败或有数学审核缺陷时优先修正，改变重复失败的路线。
3. 对有关声明运行本地构建和适当审计，再 commit、push main。重要接口和论文级成果仍需相关语义/依赖核对；声明改变后旧审核不自动有效。
4. 将真实本地构建、公理审计、源文件与固定提交的对应关系记录入台账，即可进入独立验收；不逐批等待远端三项作业或重复下载工件。直接集成以 `integration_mode=direct-main` 和实际主分支提交记录，PR 可为空。该字段不替代构建或语义验收。
5. 新数学阶段从明确的已验证基线开始，记录 `base_commit`。远端 CI 保留后台运行；重大里程碑、工具链变动或已知构建异常时按需检查。发现实际证明构建缺陷立即处理；看板或托管服务故障不阻塞独立证明工作。
6. 新任务核实环境、工具链、实际分支/HEAD 和依赖，不把环境名称当作源码版本。历史 PR 保留供追溯，必要的 PR 测试提交与分支 HEAD 仍分别记录并核实关系。

默认一个主要证明任务；独立调查或小引理可按依赖并行。任务粒度按实际进展调整：同一任务连续完成完整数学阶段及自然依赖，不逐小引理反复交接；在有意义阶段、需要合并、真实阻塞或执行限制时交付。任务停止后监督者检查目标是否完成；未完成则接续原任务，完成后按已合并基线推进下一目标。完成或反馈即接续；六小时巡检只是兜底，日摘要只是通知。调度存在时记录实际 ID、时区、投递位置；不伪造“已启用”。

## 阻塞、暂停与恢复

引理失败阻塞该目标；有独立工作则继续。允许修正论文、等价重述和调整证明路线，须保留原始版本和清晰差异，同步数学规格及覆盖映射。优先保留原始最终结论、量词和统一性；若必须实质弱化结论或增加限制，先报告具体障碍、已试路线和最小改动方案，由监督者交给用户决定。接口改善、修复编译和重构可自主处理。

用户暂停整个项目时，分别停止监督派单、处理在途任务、停用继续派单的调度，记录每项结果。停止一个对话不代表其它任务已停止。恢复时先核实未合并成果、实际限制、检查点和调度状态，再恢复接续。

运行政策仅四条：

1. 在用户现有订阅和授权范围内继续工作。
2. 不自行购买 credits、开启充值或引入额外收费服务。
3. 供应商实际报告额度或执行限制时报警并暂停新的派单，在可恢复时接续。
4. 无法读取账户用量本身不是停工条件。

账户详情只在私人通知处理，不进入项目状态或展示数据；网页统一显示“已暂停”等工作状态。

## 验收和记录

对相关 Lean 声明实际构建；论文级定理与重要接口核对陈述、量词和额外假设；宣布完成时检查声明及依赖中的未证明占位/无依据公理。正常基础公理与未清偿数学前提区别处理。增量开发检查相关目标，合并和重要里程碑覆盖对应成果，不要求每个小引理全库重建或内核重放。

用户于 2026-10-18 明确将独立验收转到本机 Agent：每完成一个完整引理或定理，主 Agent 启动独立 Agent，检查固定提交是否确为原论文命题，保留原量词、T 统一性、全状态和允许权族，并核对额外前提及公理依赖。已有 BUILT 积压也按同样方式清理，不等待已经不存在的云端副监督对话。验收 Agent 返回有具体版本的 PASS 或可定位缺陷；主 Agent 核实证据后更新唯一台账和完整论文覆盖。发现缺陷则修正、构建，并请独立 Agent 对修正版复核。执行者自检和 CI 不能代替这一步。

每个有意义的完整阶段维护 `state/progress.json`；涉及完整原文结果同时维护 `state/paper_coverage.json`。相邻辅助引理可随完整数学阶段一并验收，避免逐小引理交接。分析、报告写清原文对应、关键证明、额外前提和可定位问题即可，不重复誊写已核实旧依赖。验证后正常 commit/push；本机看板从同一 HEAD 的两份台账生成。仅当状态工具或展示逻辑改变时重跑相关回归测试；日常台账更新生成并检查一致性即可。

任务结果一次写清成果、声明、原文定位、检查、剩余依赖和下一步；总状态汇入这些事实，`PROOF_LOG.md` 只维护索引。Python 格式检查、SHA 形状和非空链接不能证明构建成功或数学忠实性。保留真实命令退出状态、工具链、固定提交与审计摘要；独立 Agent 核对源代码与原文，并核对相应本地证据。证明或依赖改变才使原验收失效；纯文档和状态提交无需重验不变的数学代码。

如需引用远端结果，只记录实际核实的运行和结论，不能把本地 PASS 写成远端成功。远端摘要迟滞时保留未知状态，使用已完成的本地验证继续，不再为常规验收追查三个作业的完整日志。历史远端证据保留原状。

本机监控看板 `http://127.0.0.1:8768/#overview` 继续保持运行和刷新，默认页面每 60 秒读取最新已提交台账；远端 CI 流程的简化不取消本机监控。
