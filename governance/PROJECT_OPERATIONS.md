# 长期运行约定

## 职责和唯一台账

一个 Dot 监督项目；Codex Web 云端任务写证明、做核对与维护；GitHub CI 记录确定提交的构建；网页展示筛选过的快照。`state/progress.json.tasks` 是唯一任务台账，不另建重复数据库或第二监督入口。

每条任务记录 ID、可定位的平台 task、目标/验收/依赖、分支与 `base_commit`、状态、PR/检查点、声明和构建证据、阻塞、已试路线、下一步。执行者在 PR 或该任务结果记录中交付；Dot 统一整合总状态，避免并行覆盖。源代码推送仓库，环境缓存和对话不能替代版本化成果。

## 接续与合并

1. 核实真实任务和 PR，再读台账，先处理不一致。已有运行任务不重复启动。
2. 同目标未合并、CI 失败或有审核反馈：继续原 task/branch/PR。保存检查点，改变失败策略或缩小目标。
3. 执行者先创建 draft PR；由 Dot 验收后转为 ready。核对待合并提交的实际构建及相关语义/依赖记录。声明改变后旧审核不自动有效；PR 的合并测试 SHA 与分支 HEAD 分别记录，需核实其关系。
4. 在启动授权范围内由 Dot 合并常规 PR；提交变化或检查失效则重新核对相关检查。主分支规则需在 GitHub 真正配置，不支持时普通合并前人工式核实同样条件。
5. 确认实际 merge commit 与主分支构建，再让下一任务从明确的已合并基线开始，记录 `base_commit`。若主分支 CI 失败，优先修复集成，保留最近稳定成果。
6. 新任务核实环境、工具链、实际分支/HEAD 和依赖，不把环境名称当作源码版本。重建与环境更新后复验并重新发布环境。

默认一个主要证明任务；独立调查或小引理可按依赖并行。任务粒度按实际进展调整：同一任务连续完成完整数学阶段及自然依赖，不逐小引理反复交接；在有意义阶段、需要合并、真实阻塞或执行限制时交付。任务停止后监督者检查目标是否完成；未完成则接续原任务，完成后按已合并基线推进下一目标。完成或反馈即接续；六小时巡检只是兜底，日摘要只是通知。调度存在时记录实际 ID、时区、投递位置；不伪造“已启用”。

## 阻塞、暂停与恢复

引理失败阻塞该目标；有独立工作则继续。允许修正论文、等价重述和调整证明路线，须保留原始版本和清晰差异，同步数学规格及覆盖映射。优先保留原始最终结论、量词和统一性；若必须实质弱化结论或增加限制，先报告具体障碍、已试路线和最小改动方案，由监督者交给用户决定。接口改善、修复编译和重构可自主处理。

用户暂停整个项目时，分别停止监督派单、处理在途任务、停用继续派单的调度，记录每项结果。停止一个对话不代表其它任务已停止。恢复时先核实未合并成果、实际限制、检查点和调度状态，再恢复接续。

运行政策仅四条：

1. 在用户现有订阅和授权范围内继续工作。
2. 不自行购买 credits、开启充值或引入额外收费服务。
3. 供应商实际报告额度或执行限制时报警并暂停新的派单，在可恢复时接续。
4. 无法读取账户用量本身不是停工条件。

账户详情只在私人通知处理，不进入项目状态或展示数据；网页统一显示“已暂停”等工作状态。

## 验收和记录

对相关 Lean 声明实际构建；论文级定理与重要接口核对陈述、量词和额外假设；宣布完成时检查声明及依赖中的未证明占位/无依据公理。正常基础公理与未清偿数学前提区别处理。增量开发检查相关目标，合并和重要里程碑覆盖对应成果，不要求每个小引理全库重建或内核重放。

PR 一次写清成果、声明、原文定位、检查、剩余依赖和下一步；总状态汇入这些事实，`PROOF_LOG.md` 只维护索引。Python 格式检查、SHA 形状和非空链接不能证明 CI 真实成功或数学忠实性。Dot 必须访问实际记录核实。
